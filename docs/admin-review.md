# 백오피스 역기획 점검 — 관리자 콘솔 · 파트너 센터

점검일: 2026-10-21 · 대상: `main` (4848e08) · 관점: 여행 커머스 백오피스 PM
목적: 구현된 화면에서 기획 의도를 거꾸로 따라가 **기획 누락 · 정책 미정의**를 찾고, 운영에서 생길 문제와 고칠 방향을 정한다. 단순 UI 버그 점검(QA)은 [review.md](review.md)에 있다.

개선 진행: 이 보고서를 근거로 관리자 콘솔을 단계별(S1~S5)로 고치고 있다. 반영한 이슈는 ID 옆에 `✅ S단계`(반영) 또는 `◐ S단계`(일부 반영)로 표시한다. A-08은 주문 처리·관리자 조치 기록과 주문 타임라인까지이고, 상품 내용·재고 수정 이력은 남기지 않는다. A-01·A-10은 관리자 주문 상세의 운영자 취소·환불 조정·CS 메모까지이고(파트너 쪽 취소, 회차 일괄 취소, 예약자 정보 수정은 아직), A-20은 정산 완료 뒤 조정 전표(S2)와 관리자 정산 상세·되돌릴 수 없다는 안내(S5)까지다(파트너 확인·지급 상태·수수료율 변경은 아직). A-17의 CSV는 연락처를 아예 빼서 내려준다(원문 열람 권한은 A-07 몫). A-18은 검색·필터·페이지까지이고 판매 중지 버튼 위치는 그대로다. A-11은 정지 시 상품 일괄 중지·영향 안내까지이고(정지 파트너의 바우처 처리, 계정 없는 파트너의 확정 상품은 아직), A-23은 관리자 조치 사유까지다(승인 메모, 고객 취소 사유 수집은 아직).

| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 서비스      | 여운(ondo) — 일본 6개 도시 여행 상품 온라인 쇼핑몰                                                                                                  |
| 상품 유형   | 투어·액티비티, 티켓·패스 (이용일 + 회차 + 성인/아동 수량 + 추가 옵션). 패키지·숙박·항공 없음                                                        |
| 판매 구조   | 입점형 마켓 — 직영 파트너 1곳 + 입점 파트너 3곳, 수수료 15% (주문 시 스냅숏), 이용월 기준 월 정산                                                   |

### 점검 방법과 제약

- 관리자 7개 화면(대시보드, 파트너 관리 3탭, 상품, 주문, 주문 상세, 리뷰 신고 2탭, 정산)을 로그인 상태로 열람했다.
- 되돌릴 수 없는 버튼은 **누르지 않았다**. `정산 완료 처리`, `판매 중지`는 확인 대화상자만 열어 문구를 읽고 `돌아가기`로 닫았다. 열람 후 해당 행 상태가 그대로(`정산 예정`, `판매 중`)인 것을 확인했다.
- 승인·거절·이용 정지·기각·리뷰 숨김·확정·거절·사용 처리·재고 적용의 동작은 **[예상 동작]**으로, 서버 액션과 DB 함수(`src/db/migrations/0010·0012·0014·0015·0017·0019`)를 따라가 적었다.
- **파트너 센터 [미확인 — 목업으로 확인]**: 파트너 4곳 모두 `계정 없음 (직영·데모)`이라 파트너로 로그인할 수 없다. 화면 구성·문구는 `/dev/components` 10·11절과 컴포넌트 코드로 확인했다.
- 고객·파트너에게 가는 알림(메일·알림톡)은 **기능 자체가 없어** 반영 여부를 볼 수 없다(→ A-09).

│   │                          / 처리할 일 칩(신청·신고·확정 대기) / 차트 3개(일별, 도시별, 종류별)
│   ├─ 파트너 /admin/partners

│   │   ├─ ?tab=done ········ 처리된 신청
│   │   └─ ?tab=partners ···· 파트너 목록 — [이용 정지]/[정지 해제] (계정 있는 파트너만)
│   ├─ 상품 /admin/products ·· 전체 목록 — [판매 중지(사유 필수)]/[판매 재개]

│   │   └─ ?tab=done ········ [숨김 해제]
│   └─ 정산 /admin/settlements?month= · 월 이동(최근 12개월) / 파트너별 합계 — [정산 완료 처리]
│
├─ 파트너 센터 /partner ······ partner만(비파트너 → /partner-apply), 이용 정지 시 안내 화면
│   ├─ 홈 /partner ··········· 확정 대기 · 오늘 이용 · 이번 달 매출

│   │   ├─ /new ············· 상품 등록

**구조상 특징**

- 관리자에게 **상품 내용 수정 · 주문 처리 · 고객 관리 · 공지/알림 · 설정(취소 규정, 수수료율, 관리자 계정)** 메뉴가 없다.
- 상품 상태는 DB enum이 아니라 4개 열(`published_at`, `unavailable_reason`, `suspended_reason` 등)의 조합으로 계산된다 → `임시 저장 / 판매 중 / 판매 일시 중단 / 판매 중지(관리자)` (`src/lib/data/partner-center.ts:51-57`).
- 주문 상태는 `paid / cancelled` 2개, 항목 상태는 `pending / confirmed / used / rejected / cancelled / expired` 6개다. 화면에서는 이용일이 지난 `confirmed`를 `이용 완료`로 바꿔 보여 준다(`src/lib/order-status.ts:35-37`).

## 6. 디벨롭 로드맵

### 즉시 수정 (오픈 전, 1~2주)

법적 리스크와 데이터 유실을 먼저 막는다. 기능 추가는 최소화한다.

1. **약관·처리방침·중개 고지 게시**, 주문서 제3자 제공 고지 (A-04)
2. **주문 cascade 삭제 차단**: `orders.user_id` → `SET NULL` 마이그레이션 (A-05)
3. **취소 규정 구간 스냅숏**: `order_items.cancel_tiers` 추가·백필, `refund_quote` 수정 (A-03)
4. **파트너 연락처 노출 제한**: `partner_bookings` 상태·기간 조건 + 마스킹 (A-06)
5. **`/dev/components` 프로덕션 차단** (A-25)
6. 정산 완료 대화상자에 "되돌릴 수 없음" 문구 추가, 바우처 사용 처리 2단계 확인 (A-20 일부, A-21)
7. 계정 없는 파트너의 `manual` 상품 저장 차단 또는 관리자 대리 확정 (A-11 ③)

### 단기 개선 (오픈 후 1~2개월)

예외 처리를 시스템 안으로 들인다. D-01·D-02·D-05·D-09를 먼저 결정한다.

1. **감사 로그** 테이블 + 주문 타임라인 (A-08) — 이후 모든 기능의 바탕
2. **운영자 취소**(항목·회차 일괄) + 귀책 코드 + 전액 환불 (A-01)
3. **환불 조정** + 정산 조정 전표 (A-02, A-20 ①)
4. **알림 1차**: 메일로 확정·거절·만료·운영자 취소·확정 기한 임박 (A-09)
5. 관리자 주문 **필터·페이지네이션·CSV**, 항목 상태 요약 (A-17)
6. 파트너 정지 시 상품 일괄 중지 + 바우처 처리 허용 (A-11), 판매 중지 사유 코드 분리 (A-12)
7. 상품 **낙관적 잠금**(version) (A-14), 재고 적용 미리보기 (A-22)
8. 사유 입력 필수화 (A-23)

### 중장기 고도화 (3~6개월)

조직이 커져도 버티는 구조로 바꾼다.

1. **관리자 역할 분리**(super·cs·md·settlement) + 개인정보 열람 로그 + 관리자 계정 관리 화면 (A-07)
2. **예약 변경**(재고 이동 + 차액 결제/환불) (A-15)
3. **최소 출발 인원** + 진행 결정 워크플로 (A-13)
4. **정산 고도화**: 파트너 확인 → 확정 → 지급 완료, 수수료율 이력, 세금계산서 연동 (A-20)
5. 노쇼 처리 워크플로 (A-19), 여행자 정보 설정형 수집 (A-16)
6. 알림톡 연동, 이용 전날 리마인드, 안심번호 (A-09, A-06)
7. 상품 검수 단계와 상품 상태 enum 전환, 관리자 수정 요청 (A-24, A-28)
8. 쿠폰·프로모션 (D-07 결정 후, A-27)
