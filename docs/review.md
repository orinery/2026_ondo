## 3. 전환(S1~S5) 중 발견해 고친 문제

| 문제                                                           | 원인                                                                                                | 수정                                                                                                  |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 마이그레이션 생성본이 적용되지 않음 (2건)                      | drizzle-kit이 `DROP TABLE … CASCADE` 뒤 같은 FK를 다시 삭제, `product_id` 컬럼보다 PK를 먼저 생성   | 생성본 순서를 직접 고치고 파일에 이유 기록. 적용 전 실제 DB에서 트랜잭션 안 실행 → 롤백으로 사전 점검 |
| 같은 트랜잭션에서 추가한 enum 값(`booking`)을 쓸 수 없음       | Postgres 제한 ("unsafe use of new value")                                                           | CHECK는 `type::text = 'booking'`으로 비교, 함수는 plpgsql(실행 시점에 해석)                           |
| 목록 필터 함수가 쿼리를 미리 실행할 뻔함                       | supabase 쿼리 빌더는 then이 있는 객체 → async 함수에서 돌려주면 await되는 순간 실행                 | 필터 적용 함수를 동기 함수로, 비동기 작업(도시 id 조회)은 밖에서                                      |
| 모바일에서 장바구니·데모가 가로로 넘침                         | 이 프로젝트의 `sm`은 360px(명세)인데 Tailwind 기본(640px)로 착각해 `sm:`을 씀 + 그리드 암묵 열 확장 | 데스크톱 분기는 `md:`로, 그리드에 `grid-cols-1`(minmax(0,1fr))                                        |
| 지도 마커가 이름 없는 버튼 (axe aria-command-name)             | Leaflet 마커는 기본으로 `role=button`·탭 이동 대상                                                  | 표시용 마커는 `interactive={false} keyboard={false}` + `title`                                        |
| 취소 확인 버튼·주문서 오류 상자 대비 4.48:1 (다크)             | shadcn destructive 변형의 옅은 빨강 배경 위 빨강 글자                                               | 확인 버튼은 채운 빨강, 오류 상자는 카드 배경 + 빨강 테두리                                            |
| 동의 없이 결제 → 휴대폰 번호가 지워짐 (사용자 확인)            | React 19 폼 액션은 끝나면 폼을 초기화 → 기본값 없는 입력만 비워짐                                   | 주문서 입력을 상태로 유지(controlled)                                                                 |
| 주문 취소 후 플래너에 빈 여행이 남음 (사용자 확인)             | 예약 항목만 지우고 자동 생성 여행은 남김                                                            | `trips.created_by_order_id` 기록, 비면 함께 삭제 (0006)                                               |
| 새 여행에 기존 예약이 안 들어옴 (사용자 확인)                  | 예약 항목은 주문 순간에만 추가                                                                      | `attach_bookings` — 여행 생성·기간 변경 시 기간 안의 예약을 붙임 (0007)                               |
| 4일 이상 여행에서 Day 탭이 넘쳐 겹치고 클릭 불가 (사용자 확인) | shadcn `TabsList`의 `group-data-horizontal/tabs:h-8`이 `h-auto`보다 우선                            | 같은 변형으로 `h-auto` 덮어쓰기 — 360에서 3줄·높이 140px, 모든 탭 클릭 확인                           |
| 예약 항목 삭제가 아무 반응 없이 끝남                           | DB 제한 정책이 0행 삭제로 막아 오류가 나지 않음                                                     | 먼저 예약 항목인지 확인해 "예약 취소로만 빠져요" 안내, 삭제 버튼 자체를 숨김                          |
| 리뷰가 없는 상품이 "★ 0.0"                                     | 평점 0이 낮은 평점처럼 보임                                                                         | "아직 리뷰가 없어요"로 표시                                                                           |

## 4. 남은 개선 후보 (적용 안 함)

- **한글 폰트 399KB**: IBM Plex Sans KR 4개 굵기. 700을 쓰지 않으므로 400·500·600으로 줄이면 감소 (명세와 달라짐)
- **서버 응답 200~500ms**: 대부분 Supabase(시드니)까지 왕복. 서울 리전으로 옮기거나, 모두에게 같은 상품·도시 데이터는 서버 캐시 적용 가능
- **예약 달력 지연 로드**: 1023 이하에서는 하단 시트를 열 때만 달력이 필요하므로 `next/dynamic`으로 분리하면 모바일 상세 JS 감소
- ~~**날짜별 재고·가격**~~ → 7절(파트너·관리자 단계)에서 회차 재고·날짜별 가격·초과 판매 방지로 구현
- **갤러리 blur-up(LQIP)**: 이미지별 blur 데이터를 시드 때 만들어 저장하면 명세대로 구현 가능

### 이 단계에서 발견해 고친 문제

| 문제                                                  | 원인                                                                    | 수정                                                           |
| ----------------------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------- |
| 정책이 아직 없는 함수(`is_admin`)를 부름              | drizzle-kit 생성본은 정책을 커스텀 SQL보다 먼저 만든다                  | 역할 함수를 앞 마이그레이션(plpgsql, 늦은 해석)으로 분리       |
| 기존 행이 있는 테이블에 NOT NULL 컬럼                 | 생성본 그대로면 기존 상품·주문 항목에서 실패                            | NULL 허용으로 추가 → 백필 → NOT NULL (파일에 이유)             |
| 공개 프로필에 역할이 노출될 수 있음                   | 테이블 단위 SELECT 권한은 컬럼을 골라 막을 수 없다                      | SELECT 회수 후 공개 컬럼만 재부여, 본인 역할은 `my_profile()`  |
| 바우처 사용 처리 실패                                 | `smallint + smallint` 결과를 integer 반환 열로 선언                     | 검증 스크립트가 발견 → 0015로 수정 (적용된 파일은 고치지 않음) |
| 운영 사이트(옛 코드)가 날짜별 가격 상품에서 결제 실패 | DB를 먼저 바꿔 옛 장바구니 금액(기본가)과 DB 금액(덮어쓴 가격)이 달라짐 | 장바구니 금액 계산을 S2에서 바로 고쳐 함께 푸시                |
| 쇼케이스 콘솔이 랜드마크·제목 순서 위반               | 콘솔 셸·장바구니 요약이 다른 섹션 안에 들어감                           | `preview`일 때 aside 대신 div, 제목 단계 지정(`as="h2"`)       |
| 좁은 화면의 정산 표를 키보드로 스크롤 불가            | 표 안에 포커스 요소가 없음 (axe scrollable-region-focusable)            | 표 컨테이너를 이름 있는 포커스 가능 영역으로 (`scrollLabel`)   |
| 상품 목록 제목 단계 h1 → h3                           | 카드 제목 앞에 구역 제목 없음                                           | 화면에는 안 보이는 h2 "상품 목록"                              |
| 로그인 페이지 장식 사진 영역이 랜드마크 밖            | 768 이상에서만 보이는 계절 사진·문구                                    | 장식이라 `aria-hidden`                                         |

### 확인 방법의 한계

- 파트너·관리자·고객 화면은 실제 로그인이 필요해 자동 점검은 `/dev/components` 목업으로 했다. 실제 흐름(신청 → 승인 → 상품 등록 → 예약 → 확정 → 바우처 → 정산)은 사용자가 직접 확인한다.
- 예약 위젯의 클릭 동작은 브라우저 창이 가려져 있으면 하이드레이션이 진행되지 않아 일부만 확인했고, 계산 로직은 순수 함수 스크립트로 따로 확인했다.
