# 8단계 점검 보고서

점검일: 2026-10-15 · 대상: `main` (474b709) + 8단계 수정분 · 환경: 프로덕션 빌드(`next start`), Chromium

## 1. 점검 방법

| 항목           | 방법                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| 반응형         | 360 / 768 / 1280 너비의 iframe에서 공개 페이지 8개를 열고 가로 넘침(scrollWidth)과 화면 밖으로 나간 요소를 측정       |
| 다크 모드·대비 | `globals.css`의 라이트/다크 토큰으로 실제 쓰인 글자·배경 조합 26쌍의 WCAG 대비를 계산 / 테마 고정 색 사용처 전수 확인 |
| 접근성         | axe-core 4.10.2로 WCAG 2.1 A·AA 규칙 자동 검사 (6개 페이지 × 360·1280)                                                |
| 성능           | 페이지별 전송량(JS·CSS·폰트·이미지), 서버 응답 시간 3회 측정                                                          |
| 권한           | `npm run db:verify-rls` 31개 시나리오                                                                                 |
| 명세 대조      | 명세 4.1~4.5(페이지)·5.1~5.5(컴포넌트)의 항목별 구현 여부                                                             |

로그인이 필요한 `/my`(찜 목록·플래너)는 자동 점검 대상에서 빠졌다. 로그인은 사용자가 직접 확인한다.

### 성능 측정값 (1280, 압축 전송량)

| 페이지                | JS    | CSS  | 폰트  | HTML | 요청 수 | 서버 응답 완료 |
| --------------------- | ----- | ---- | ----- | ---- | ------- | -------------- |
| `/`                   | 252KB | 81KB | 351KB | 19KB | 62      | 200~250ms      |
| `/destinations`       | 264KB | 81KB | 351KB | 18KB | 65      | 210~450ms      |
| `/destinations/kyoto` | 364KB | 81KB | 351KB | 23KB | 65      | 330~610ms      |

- 응답 시간 대부분은 Supabase(시드니 리전)까지의 왕복이다. 로그인 페이지는 DB를 조회하지 않아 10ms.
- 폰트 351KB: 한글 폰트(IBM Plex Sans KR) 4개 굵기의 유니코드 분할 파일.
- 상세 JS가 100KB 더 큰 이유: 갤러리(embla)·지도(Leaflet, 지연 로드)·리뷰 다이얼로그, 그리고 읽기 전용 추천 일정이 드래그 라이브러리(dnd-kit)까지 함께 불러온다.

## 4. 남은 개선 후보 (적용 안 함)

- **한글 폰트 351KB**: IBM Plex Sans KR 4개 굵기. 실제로 700은 쓰지 않으므로 400·500·600으로 줄이면 감소 (명세와 달라짐)
- **서버 응답 200~600ms**: 대부분 Supabase(시드니)까지 왕복. 서울 리전 프로젝트로 옮기거나, 여행지처럼 모두에게 같은 공개 데이터는 서버 캐시 적용 가능
- **갤러리 blur-up(LQIP)**: 이미지별 blur 데이터를 시드 때 만들어 저장하면 명세대로 구현 가능
